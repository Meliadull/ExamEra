# ЗАДАНИЕ ДЛЯ UI/UX-ДИЗАЙНЕРА

## Проект: ExamEra

### 1. Общая информация

Необходимо разработать современный, профессиональный, удобный и визуально целостный дизайн веб-платформы **ExamEra**.

**ExamEra** — цифровая образовательная платформа для автоматизации процессов:

- создания тестов;
- проведения онлайн-тестирования;
- проверки знаний учащихся;
- автоматической оценки результатов;
- мониторинга успеваемости;
- анализа результатов;
- формирования статистики и отчётности.

Основная задача дизайна — сделать сложный процесс управления тестированием максимально простым, понятным и быстрым для преподавателя и учащегося.

---

# 2. Основная концепция

Ключевой пользовательский сценарий платформы:

**Учитель создаёт тест → назначает его учащимся → учащиеся проходят тест → ExamEra автоматически проверяет ответы → формирует результаты → учитель получает аналитику.**

Интерфейс должен визуально поддерживать этот процесс и минимизировать количество действий пользователя.

Платформа не должна восприниматься как сложная административная система.

Она должна выглядеть как современный образовательный SaaS-продукт.

---

# 3. Целевая аудитория

Дизайн разрабатывается для четырёх типов пользователей:

### Учитель

Основной пользователь системы.

Использует платформу для:

- создания тестов;
- управления вопросами;
- назначения тестов;
- просмотра учащихся;
- анализа результатов;
- формирования отчётов.

### Ученик

Использует систему для:

- просмотра назначенных тестов;
- прохождения тестирования;
- просмотра своих результатов;
- мониторинга собственного прогресса.

### Администратор

Использует систему для:

- управления пользователями;
- управления ролями;
- управления группами;
- настройки системы;
- просмотра общей аналитики.

### Аудитор

Использует систему преимущественно для просмотра:

- результатов;
- активности;
- статистики;
- действий пользователей;
- журнала аудита.

Для аудитора изменение данных должно быть недоступно.

# 4. Общий стиль

Дизайн должен быть:

- современным;
- минималистичным;
- технологичным;
- лёгким;
- профессиональным;
- визуально чистым;
- ориентированным на данные;
- удобным для длительной работы.

Необходимо избегать:

- перегруженных экранов;
- чрезмерного количества цветов;
- слишком большого количества карточек;
- устаревших таблиц;
- мелкого текста;
- сложных многоуровневых меню;
- декоративных элементов, не имеющих функционального назначения.

Визуально продукт должен соответствовать уровню современных SaaS-, EdTech- и аналитических платформ.

# 33. Empty States

Не использовать пустые белые страницы.

Например:

# Пока нет тестов

Создайте свой первый тест и назначьте его учащимся.

**+ Создать тест**

Для результатов:

# Результатов пока нет

Результаты появятся после того, как учащиеся завершат тестирование.

---

# 34. Loading States

Для загрузки данных предусмотреть:

- Skeleton loaders;
- progress indicators;
- disabled actions во время выполнения запроса.

Избегать бесконтекстных постоянных spinner-анимаций.

---

# 35. Ошибки

Ошибки должны объяснять:

1. что произошло;
2. почему, если причина известна;
3. что пользователь может сделать.

Плохой вариант:

**Ошибка 400**

Предпочтительный вариант:

**Не удалось сохранить тест. Проверьте подключение к интернету и повторите попытку.**

---

# 36. Формы

Формы должны иметь:

- понятные Label;
- Placeholder только как дополнительную подсказку;
- описание сложных полей;
- inline validation;
- сообщения об ошибках.

Ошибки должны отображаться непосредственно возле соответствующего поля.

Необходимо соблюдать основные принципы доступности:

- достаточный цветовой контраст;
- читаемый размер текста;
- понятные состояния Focus;
- кликабельная зона элементов не должна быть слишком маленькой;
- информация не должна передаваться только цветом;
- формы должны иметь явные подписи;
- интерактивные элементы должны визуально отличаться от обычного текста.

Минимальный набор:

- Typography;
- Spacing;
- Grid;
- Buttons;
- Inputs;
- Select;
- Dropdown;
- Checkbox;

- Pagination;
- Modal;
- Tooltip;
- Toast;
- Badge;
- Avatar;
- Progress;
- Charts;
- Date Picker;
- Calendar;
- Sidebar;
- Navigation;
- Breadcrumbs.

---

# 40. Компоненты должны иметь варианты

Например:

### Button

- Primary;
- Secondary;
- Tertiary;
- Destructive.

Размеры:

- Small;
- Medium;
- Large.

Состояния:

- Default;
- Hover;
- Pressed;
- Focus;
- Disabled;
- Loading.

---

# 41. Типографика

Должна использоваться единая система.

Например:

- Display;
- H1;
- H2;
- H3;
- Body;
- Small;
- Caption.

Основной текст должен легко читаться даже при длительной работе с платформой.

---

# 42. Сетка

Для desktop рекомендуется использовать:

**12-column grid**

Основная область должна иметь ограниченную максимальную ширину и достаточные внутренние отступы.

Важно соблюдать единую spacing-систему во всём продукте.

---

# 43. Иконки

Использовать единый набор современных outline-иконок.

Иконки не должны смешиваться из разных визуальных библиотек.

Необходимо избегать декоративных 3D-иконок внутри рабочих таблиц и форм.

---

# 44. Работа с цветом

Основной цвет должен формировать узнаваемость ExamEra.

Дополнительные semantic colors:

- Success;
- Warning;
- Error;
- Information;
- Neutral.

Цвет должен помогать ориентироваться в интерфейсе, а не использоваться исключительно ради украшения.

---

# 45. Требования к таблицам

Поскольку система содержит большое количество данных, таблицы являются важным UI-компонентом.

Необходимо предусмотреть:

- поиск;
- сортировку;
- фильтры;
- pagination;
- выбор строк;
- contextual actions;
- sticky header при необходимости;
- responsive behavior.

---

# 46. Модальные окна

Modal использовать только для коротких операций:

- подтверждение удаления;
- назначение;
- изменение небольшого количества параметров.

Сложные формы должны открываться как отдельная страница или Side Panel.

---

# 47. Основные пользовательские сценарии для прототипа

Дизайнер должен подготовить кликабельный прототип минимум для следующих сценариев:

### Flow 1

**Login → Dashboard**

### Flow 2

**Dashboard → Создать тест → Добавить вопросы → Настройки → Опубликовать**

### Flow 3

**Тест → Назначить группе**

### Flow 4

**Ученик → Мои тесты → Начать тест → Ответить → Завершить → Результат**

### Flow 5

**Учитель → Результаты → Тест → Детальная аналитика**

### Flow 6

**Учитель → Учащиеся → Карточка ученика → Прогресс**

### Flow 7

**Расписание → Выбрать тест → Просмотреть детали**

# 52. Главный UX-принцип

Пользователь должен иметь возможность выполнить основные действия без длительного обучения системе.

Ключевые действия:

**Создать тест**

**Назначить тест**

**Пройти тест**

**Посмотреть результат**

**Проанализировать успеваемость**

должны выполняться максимально быстро, последовательно и понятно.

Главная идея интерфейса ExamEra:

> **«От создания теста до аналитики — в одном понятном цифровом пространстве».**
